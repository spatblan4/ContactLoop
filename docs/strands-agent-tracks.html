Phase 0 — 现有 Agent 产品化
Done

New features

  • Hooks 只读守卫：outreach_agent_hooks.py（ReadOnlyToolGuard，BeforeToolCallEvent.cancel_tool + AfterToolCallEvent 记录），使「agent 永不写 follow-up」成为代码级保证；
  • Bedrock Guardrails：BedrockModel(guardrail_id, guardrail_version, guardrail_trace) 接入，配置见 config.py / .env.example；
  • OTel 追踪：agent_telemetry.py（StrandsTelemetry 控制台 / OTLP 开关）+ Agent(trace_attributes) 携带 owner_id；
  • 测试用 FakeModel：tests/fake_strands_model.py 实现 Model 接口，驱动真实 agent loop；
  • 新测试 tests/test_outreach_agent_loop.py：读守卫拦截 / 白名单放行 / 生产接线 / 守卫单元，由 FakeModel 驱动真实 loop；另有 agent 超时用例（test_outreach_plan.py）。

Fixes

  • 修复 agent 被阻塞 / 超时时错误语义，未构建候选时快速返回；
  • agent 输出仍在 outreach_plan_client.invoke_outreach_agent 内按授权候选集二次校验（含 logger.error 告警）；
  • 确认 import 卫生：outreach_plan_agent / agent_telemetry / outreach_agent_hooks 顶层不引 strands，缺依赖时不破坏 ai_briefs.py 导入。

遗留 / 建议（来自 Phase 0 代码评审，供后续任务）： (1) 超时用 cancel_futures=True 无法中断已运行的 Bedrock 线程 → 已解决（Phase 1 传入 cancel_signal=threading.Event）； (2) 「shadow 观察」目标未完全落地：当前配置即为全阻断（guardrail_trace="enabled"），未接入 ApplyGuardrail 仅记录不阻断的 shadow 模式，误杀率需靠拦截日志观察（SDK 1.55.1 流式路径已解析 guardrail trace）； (3) guardrail_redact_output（默认 False）未暴露 → 已解决（Phase 2 暴露为 BEDROCK_GUARDRAIL_REDACT_OUTPUT）； (4) 守卫对 MCP / context_manager="agentic" 注入工具会误拦 → 已解决（Phase 2 改为分来源放行策略）； (5) test_outreach_agent_loop.py 依赖 strands 安装，未装 requirements-bedrock.txt 时整组 skip，CI 需装依赖才能真验证。

Phase 1 — 会话与多轮交互
Done

New features

  • 多轮 Outreach 问答：POST /outreach-plan/ask（QA agent 基于授权候选事实作答），SummarizingConversationManager 控上下文；
  • SessionManager 持久化：agent_sessions / agent_session_agents / agent_session_messages 三表 + SqlAgentSessionRepository 实现 Strands SessionRepository 接口（SQLite / Supabase Postgres 双方言），按 teacher_id 隔离，会话恢复经 RepositorySessionManager；
  • 会话读取 / 重置：GET / DELETE /outreach-plan/conversation（软删 tombstone + 子行清理）；
  • SSE 流式生成：POST /ai/outreach-plan/generate/stream（candidates / message / plan / error 事件，复用授权集校验与超时取消），前端 generateOutreachPlanStream 消费并显示进度。

Fixes

  • Phase 0 遗留 (1)：超时改为可取消——cancel_signal=threading.Event 全链路传入 agent()，超时后 set，agent loop 在下一 checkpoint 中止在途模型调用；
  • SSE 路径的越权学生检查与客户端路径共用 unauthorized_students_present（兼容 dict / pydantic 两种 item 形态）；
  • 端点异常补日志（此前被静默折叠为 error 事件）；
  • Phase 1 代码评审修复：QA 工具入参改传 model_dump(mode="json") 化候选——原样传 pydantic 模型会在真实 BedrockModel 序列化工具输出时报错（FakeModel 测试路径无法暴露）。

测试：问答持久化与恢复、教师间隔离、重置、503/401；SSE plan/error 两分支；前端 SSE 解析 3 例。全部走 FakeModel，不触网。

评审遗留（已知限制，暂接受）： (1) 同一教师并发 /ask 可能撞 session_id 唯一约束 → 503（单教师场景可接受，后续可捕获 IntegrityError 降级）； (2) AgentSessionMessage.preview() 尚无调用方； (3) 会话查询按 session_id（由 qa_session_id(user_id) 派生）隔离而非 join 校验 user_id，语义等价但依赖派生规则。

Phase 2 — Agent 能力扩展
Done

New features

  • owner-scoped 只读工具：outreach_tools.py 提供 get_contact_history / get_open_follow_ups / get_teacher_notes，每工具走 require_owned_*，返回脱敏最小化数据；QA agent 守卫白名单同步扩展；
  • 通话摘要草稿：POST /ai/call-summary/generate（Connected 事件 → agent 草稿 → teacher_confirmed=false、source='ai' 的 teacher_note）；
  • 语音笔记真链路：voice_transcription.py（Amazon Transcribe 可选 + 后台线程 + 草稿落库，未配置时保留存根行为）；teacher_note source 枚举扩展 'ai'；
  • Agents-as-Tools 协调者：POST /teacher-assistant/ask（outreach_coordinator.py）把 outreach planner / 问答器 / 摘要器组合为 agent.as_tool()，协调者守卫只放行三个专家工具，会话按教师持久化；
  • Graph 质量流水线：summary_pipeline.py 用 Strands Graph 实现 草稿 → LLM-as-judge 自审 → 终稿 的条件环（judge 判 APPROVED 或 REVISE: ），CALL_SUMMARY_QUALITY_PIPELINE=true 时替代单次调用，无终稿一律 fail-closed；
  • MCP 只读面：outreach_mcp.py（ReadonlyMcpTools）从可选 MCP server 加载 MCP_ALLOWED_TOOLS 白名单内的只读工具接入 QA agent，加载失败降级为无 MCP 工具；
  • Bedrock Guardrails 输出脱敏：BEDROCK_GUARDRAIL_REDACT_OUTPUT 透传到 BedrockModel（Phase 0 遗留 (3)）。

Fixes

  • Phase 0 遗留 (4) 解决：守卫改为分来源放行策略——显式白名单 + allowed_prefixes（外部只读工具前缀）+ SDK 注入工具（retrieve_context），MCP / agentic context manager 不再被误拦；
  • 语音转写后台线程只传值对象（避免 ORM 跨会话 detached 访问）；
  • 前端 teacherNoteSourceLabel 识别 ai 来源并标注 "needs review"；
  • Phase 2 代码评审修复（2026-09-13）： call-summary / 语音草稿路径补超时与取消——新增 draft_note_content_bounded（线程池 + outreach_agent_timeout_seconds + cancel_signal，与 plan / QA 路径对齐），接入 generate_call_summary 与语音后台 _finalize_draft，并补超时取消测试（原该路径挂起的 Bedrock 调用或 Graph 修订环会无限占用请求 worker，违反「超时可取消全链路」约定）； teacher_assistant.py 端点异常补日志（Phase 1 评审刚确立的模式，新端点回归遗漏）； ask_teacher_assistant 候选集改为一次构建经 candidates= 透传（原重复查询两次）； 硬编码收敛：超时 fallback 常量统一到 config.py 单一来源（原 4 处模块级拷贝），会话上下文保留条数与修订环上限改为配置（AGENT_PRESERVE_RECENT_MESSAGES、SUMMARY_PIPELINE_MAX_NODE_EXECUTIONS）。
  • Phase 1 评审连带修复（本批文件）： transcribe_enabled() 补验 voice_transcribe_bucket（原启用但缺桶时后台任务直接失败）； Transcribe 轮询加 300s 上限（原 while True 无界）； 转写任务记录 user_id，GET /voice/transcriptions/{job_id} 校验归属（原任意登录用户可查询任意任务）； create_teacher_note_draft 补 require_owned_student（服务层 fail-closed，不再仅依赖调用方校验）； outreach_tools 的 history / notes 过滤下推 DAO（student_id + owner_id，原全量拉取后 Python 过滤）； 清理 voice.py 中遮蔽导入的重复 TRANSCRIPT_STUB 定义。

测试：owner 工具隔离（含越权 404）、call-summary 草稿 + 越权 + 流水线开关与 fail-closed、语音转写归属/上限、协调者路由/守卫拦截/端点 503/401、Graph 流水线 直批/修订/不批/含糊裁决、MCP 白名单解析/门控/降级/QA 接线、草稿超时取消。全部 FakeModel 驱动，不触网（后端 162 / 前端 145 全绿）。前端入口已接入：Outreach 计划卡片下 QA 问答框（会话恢复 / 重置）、Contact history 的 Connected 事件「Draft summary」按钮、侧边栏 Teacher Assistant 模态。

已知限制（暂接受）： (1) Graph 流水线节点内的模型调用不消费 cancel_signal：整体已由 draft_note_content_bounded 的 90s 超时兜底（请求 worker 不再被挂起），但超时后孤儿线程仍会跑到节点执行上限才结束； (2) MCP 工具加载发生在每次 QA 请求内（无缓存），server 不可达时每问一次都会重试一次连接（fail-safe 降级）； (3) 协调者的 planner 专家在 as_tool 形态下产出文本计划（无 structured output 校验），正式 outreach 计划仍走原端点； (4) 协调者内 QA 专家无独立 session（仅协调者会话持久化），多轮上下文由协调者携带。
